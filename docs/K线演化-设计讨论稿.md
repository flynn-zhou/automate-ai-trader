## 一、一句话定位

**每根（指定周期的）K 线收盘时，输出一份多维读数：K 线结构、观察线反应、量能、
区间演化空间位置。** 接生产、逐根算、周期由使用者指定。目的是辅助进场与离场。

**不是**「给一根 K 线做分类」，也**不是**判断哪条线是支撑。

**不挂区间演化。** 区间演化只是观察线之一，是四维读数里的**一维**，不是框架。
用户原话：「我本意是不跟区间演化挂钩的，因为一个 K 线可能在 ema20 就拒绝，
你不能只看区间演化的几个价格，K 线演化看的更多」。

## 二、区间演化的周期是 1h（实测，v2 写错的地方）

服务器实测（`data/market_range.db`）：

    ts=1794027600000  ts_h=2026-11-07 13:00
    ts=1794024000000  ts_h=2026-11-07 12:00     <- 步长 3,600,000ms = 1 小时
    range_evolution 行数=2264   bars_1h 行数=2264
    跨度 2026-08-05 06:00 ~ 2026-11-07 13:00   小时数=2263   行数/小时=1.00

**15m 只是输入 CSV 的粒度**（`data/range_bars_15m.csv`）。引擎用 4 根 15m
合成 1h 完整桶（`engine.py::load_1h`），状态机跑在 **1h** 上。

所以：**区间演化四线是 1h 周期的观察线。**

## 三、为什么先做 15m（正确的理由）

用户倾向先做 15m。v2 给的理由「能和区间演化逐根对齐验证」是**错的**，因为
区间演化是 1h。正确理由有三条：

1. **样本量。** 1h 只有 2264 根（约 94 天）。研究「观察线上的反应」需要样本，
   15m 约 9000 根，是 1h 的 4 倍。
2. **15m 是原生粒度。** 3s 桶聚成 15m 无损，1h 是 15m 再聚合。
   从原生粒度做，少一层间接。
3. **15m K 线 × 1h 观察线 = 天然的多周期场景。** 这正是我们要验证的核心情形：
   一根 15m K 线遇到 1h 的 EMA200、1h 的区间演化硬边界。
   如果只做 1h，永远测不到「低周期遇到高周期线」这件事。

**验证方式随之改变**：不是「逐根对齐」，而是
**在整点收盘处核对 1h 观察线价格 == `range_evolution` 对应字段**。
这是可做的：每个整点的 1h 线价格必须和库里那根 1h 的状态一致。

## 四、核心概念：观察线（不是支撑线）

用户原话：

> 「任何指标，比如黄金分割线，ema20/200 等都不是支撑线，只是观察线！
> 观察线就是不要直接动手上仓位，你得观察价格在这里的反应，
> 具体反应怎么看是支撑，怎么看是短暂停留！」

**「支撑线」是断言，「观察线」是观测位。**

- 说「EMA20 是支撑」—— 无法验证。跌破就改口说「有效跌破」，永远自洽。
- 说「价格在 EMA20 上有反应」—— 可以记录、可以数、可以统计。

**支撑不是线的属性，是反应的统计结果。** 一条线被反复守住，事后才叫支撑；
事前它只是个观测位。

所以本能力**不判断哪条线是支撑**，只记录在每条观察线上发生了什么。

**每条观察线必须带自己的周期。**

    EMA200 在 15m 上和 EMA200 在 1h 上，是完全不同的两条线。
    一条观察线的身份 = (种类, 周期, 参数, 价格)

## 六、数据模型（三张表，物理隔开当下与事后）

### 表 1：`kbar_evolution` —— 每根 K 线一行（当下读数）

    -- 身份
    symbol TEXT, interval_ms INT, ts INT (bar 开盘时间, ms UTC), idx INT
    -- 区间演化空间位置（1h 维度，只是四维之一）
    range_ts_h INT, fam INT, seg INT, seg_idx INT, direction TEXT, zone TEXT
    -- K 线结构
    o REAL, h REAL, l REAL, c REAL, dir INT
    body_pct REAL, up_wick_pct REAL, dn_wick_pct REAL, close_pos REAL
    -- 量能
    vol REAL, vol_rel REAL, vol_slot_rel REAL, taker_buy_ratio REAL, conc REAL
    -- 内路径（3s）
    path_shape TEXT, max_tick_share REAL, t_low_min INT, t_high_min INT
    -- 观察线反应汇总
    n_lines INT, n_touch INT, n_break INT
    -- 事件
    event TEXT, prev_event TEXT, on_line TEXT, since_event_idx INT, state TEXT

### 表 2：`kbar_reaction` —— 每根 K 线 x 每条碰到的观察线（当下读数）

    symbol, interval_ms, ts,
    line_key TEXT,        -- 唯一标识: "ema200@1h" / "range_hard_up@1h" / "donchian_lo@15m"
    line_kind TEXT, line_period_ms INT, line_price REAL, dist_pct REAL,
    touch INT,            -- 0/1 本根是否触及
    side TEXT,            -- from_above / from_below
    pen_depth_pct REAL,   -- 穿透深度
    recover_pct REAL,     -- 收回幅度
    close_side TEXT,      -- above / below
    dwell_bars INT,       -- 连续多少根贴着
    vol_rel REAL, taker_buy_ratio REAL,
    nth_touch INT         -- 第几次触碰（按区间演化换段重置）

### 表 3：`kbar_forward` —— 事后确认（**禁止参与当下判定**）

    symbol, interval_ms, ts, ret1 REAL, ret3 REAL, ret5 REAL, held INT

**为什么必须分三张表**：「之后涨了」是事后信息。混进当下读数，回测就偷未来。
（本项目 1h forming 桶永不落库，就是同一个纪律。）
物理隔开比靠自觉可靠 —— 当下判定代码**不许 import** `kbar_forward` 的读取函数。

## 七、口径定义（现在必须定死，否则算不出来）

    实体占比   body_pct      = |c - o| / (h - l)
    收盘位置   close_pos     = (c - l) / (h - l)        0=最低 1=最高
    上影       up_wick_pct   = (h - max(o,c)) / (h - l)
    下影       dn_wick_pct   = (min(o,c) - l) / (h - l)
    相对量     vol_rel       = vol / median(vol, 前 20 根)
    时段相对   vol_slot_rel  = vol / median(同小时的历史量)   （日内效应很强）
    主动占比   taker_buy_ratio = taker买量 / 总量
    集中度     conc          = 最大单根 3s 桶量 / 这根总量
    穿透深度   pen_depth_pct = 从上方来: (p - l)/p ; 从下方来: (h - p)/p
    收回幅度   recover_pct   = 从上方来: (c - l)/p ; 从下方来: (h - c)/p
    距离       dist_pct      = (c - p) / p * 100

**口径不是判断标准。** 口径只是「怎么算」，不预设「多少算好」。
所有口径参数（如 vol_rel 的 N=20）必须显式存进代码常量并在文档留痕，可改。

## 八、事件层：转移标签，允许 neutral

### 8.1 回溯是动态的，不是定死 N 根

用户：「也可能需要看 332/331/330 等，这个不是定死的，
因为有的 K 可能没什么意义，假如在区间中间的时候」。

做法：**不存「前一根是什么」，存「上一件同类事件是什么」。**

    since_event_idx   距上次同类事件多少根
    prev_event        同类事件的上一次是什么
    on_line           这个事件发生在哪条观察线上

这样「#334 收回」天然能引用 #333，中间无意义的 K 不打断链条，隔 20 根也能连上。

### 8.2 允许「无意义」

    state = neutral    没碰到任何观察线、量正常、在空间中间

区间中间大量 K 是 neutral。**强行给每根贴标签，就是在制造噪声。**

### 8.3 词表：复用区间演化，不另造

`range/engine.py` 已有：`birth` / `区间成形` / `向上突破` / `向下突破` /
`突破失败·反包` / `反向边界插针上移` / `R滚动` / `向上反转` / `向下反转`。

K 线演化的事件**沿用这套名字**，但**突破对象不限于区间演化边界** ——
EMA、唐奇安、结构位都能被突破，所以事件必须带 `on_line`。

### 8.4 不许自由文本

不能写「主力在诱多」。只能是 `event=收回, prev_event=向上突破, on_line=range_hard_up@1h`。

## 九、「是支撑还是短暂停留」怎么变成可算的

不定义「支撑」。把「反应」记录到足够细，「守住」与「短暂停留」的差别自然浮出：

| | 守住 | 短暂停留 |
|---|---|---|
| 穿透深度 | 浅 | 深 |
| 收回 | 快、收盘回到线上 | 慢、收盘在线下 |
| 量 | 不大（没人真想打穿） | 很大 |
| 停留根数 | 多（反复试探） | 少（一根就走） |
| 下一根 | 反向离开 | 继续走 |

**这两者的差别是数据能分辨的，而「这条线是支撑」不是。**

## 十一、我们真正的数据优势（必须用上）

看 K 线的人只有 4 个价格加 1 个量。
**本地有 187992 根 3s 桶，每笔带主动买卖方向（`is_buy`）。**

同一根长下影，别人只看到长下影，我们能看到它是：

- 一根 3s 桶瞬间砸下去的（流动性真空，恐慌）
- 还是慢慢阴跌 40 分钟然后拉回（承接，吸收）

**两者在 K 线上完全同形，含义相反。** 落成 `conc`（集中度）与 `path_shape`（内路径）。
