## 一、这是什么

automate-ai-trader：自主 BTC 永续交易系统。用户只做一件事——往合约账户打钱（目标 100 USDT）。
其余全自动：3s 行情 → 信号 → 风控闸 → 开/管/平 → 全过程落库并在大屏可见。
唯一目标：赚钱，归零可接受。

与 automate-k-trader（老系统）平级独立，共用同一个 Binance API Key，上线时停掉老系统。
老系统的交易设计已被数据证明失败（1 年 -266U、含费 -1151U、真实 120 天 -1983U），不要学。

## 三、代码地图

- feed.py 行情主管线（WS 逐笔 + REST aggTrades 兜底 → 3s 桶 → 多周期 → 落库+广播）
- market/agg.py 多周期聚合（3s 是原子事实）；market/rest.py 含 aggTrades 游标增量；market/ws.py 只做加速
- store.py K 线库；trade_db.py 交易审计库；journal.py 研究日志库；guard.py 无人值守闸
- trading/features.py 特征（sigma 自适应）；signals.py 三个信号入口；risk.py 风险预算+五道闸；engine.py 决策主循环

- tools/ tcp_tunnel.py（隧道）、journal_add.py（写日志）、snapshot_state.py（态势快照）、seed_journal.py

## 五、下一步

> 现状：**账户还没打钱**。现货钱包里有 0.52877786 USDT（合约钱包的钱要转到现货钱包），
> paper 模式在跑，趋势策略处于空仓等待（价格低于 SMA200 约 5.5%）。

按顺序，前两条只能由人做，第 3 条之后是系统自己：

1. **把钱转到现货钱包**（不是合约钱包）。本系统跑现货，合约钱包里的钱它看不见。
2. 在 `/etc/ai-trader/env` 里写 `AI_API_KEY` / `AI_API_SECRET`，设 `AI_TRADE_MODE=live`，
   然后 `systemctl stop cryptobot`（停掉老系统，两个系统不能同时用同一个 Key 交易）。
3. **先跑体检再重启**：`AI_TRADE_MODE=live .venv/bin/python tools/preflight_live.py`，
   退出码 0 才是 GO。它会查配置、记账库、凭证、交易所连通、资金是否够开首单、时钟、当下策略状态。
4. 重启后盯大屏的因果链：同一条链上应当同时看到
   「开多触发线」+「均线自己下来的天数」+「六道闸是否放行」+「执行器是否熔断」。
   任何一项缺失都说明因果链又只剩一半。

防呆提醒（都是踩过的）：
- 部署只看 `systemctl is-active` 会骗人——必须比对 md5 或 grep 确认内容落地（六点五十六的教训）。
- `AI_TRADE_MODE` 写错不会报错，只会安静地继续纸面。
- 现货首单最小名义 5U、最小步进 0.00001；保证金不够时下单会被拒，`_fee_buffer` 就是为这个留的。
