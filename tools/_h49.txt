## 六点四十九、决策口径分歧：回测用现货 K 线，线上用合约 K 线

### 一、先做就绪审计（全部通过）

钱到账之前，主动问一次「还差什么」：

| 项目 | 结果 |
|---|---|
| 3s 行情 | 距今 **7 秒** |
| 4h 行情 | 距今 **3.4 小时**（4h 周期，正常） |
| 订单数学 | 71.77 / 100 / 50U × 两个价位，qty 全部符合 step、满足 minQty、满足 minNotional 5U、杠杆 ≤ 1.00x |
| 补数自愈 | 历史不足时**每 30 分钟**重试，不是只在启动补一次 |
| 资金提示 | 0.53U 时明确报「建一手至少需要 5.00U 名义｜请确认 USDT 在**现货**钱包」 |

> 订单数学这项值得说：现货 step `0.00001` 意味着一手约 **0.78U**，最小名义 5U。100U 账户在 78000 时算出 `0.00127 BTC = 99.06U`，合规。
> 如果当初选了永续（最小手 `0.001 BTC ≈ 77.8U`），100U 账户会被卡死。

### 二、顺着审计挖出的真问题

回测与信号一致性验证用的是**现货** K 线：`https://api.binance.com/api/v3/klines`
而线上 `seed_from_rest` 一直用**永续合约** K 线：`/fapi/v1/klines`

> 也就是说：**回测验证的那个世界，和线上实际决策的那个世界，不是同一个市场的价格。**

量化差距（2000 根 4h = 333 天）：

| 指标 | 数值 |
|---|---|
| 收盘价差异（中位 / 最大） | 0.046% / 0.080% |
| SMA200 最大相对差 | 0.048% |
| **above 判定分歧** | **2 / 1799 = 0.11%** |
| 分歧位置 | 全部落在「离 SMA200 < 0.1%」的临界带（20 根中 2 根） |

离均线超过 0.1% 时**从无分歧**。换句话说，分歧只发生在穿越点上——恰好就是信号真正触发的那一刻。

影响有限：最多把入场挪一根，而延迟 1 根的代价几乎为零（`0根 33.15 / 1根 33.26 / 2根 17.98`）。但两个市场这个偏差没必要留着。

**修法**：`TrendStrategy` 增加 `exec_market`，现货走 `api.binance.com/api/v3/klines`，永续仍走 `fapi`。

**线上决定性证据**：

```
线上 SMA = 82376.8533
现货口径 = 82376.8533   差 0.0000    <- 一致
合约口径 = 82337.4335   差 39.4198
```

之前线上报的 `82337.4` 就是合约口径。改动真的生效了。

### 三、这轮我两次差点骗自己

**第一次**：查 SMA 时发现线上 `82376.85` 与「200 根均值 `82349.31`」差 27.5，以为窗口错位。
查下去发现两边数据完全对齐（共同 419 个时间戳，差 `0.000000`），差的是**口径**：
回测 `sma(i,n)=sum(C[i-n:i])` **不含第 i 根**，`state()` 用的 `cl[-(n+1):-1]` 正是它。
我用「含最后一根」去比「不含最后一根」，得出的差异是我自己的算术错。**不是缺陷，第 11 个反转。**

**第二次**：写测试 `test_engine_passes_exec_market`，声称验证「引擎必须显式传市场」。
变异检查时把引擎那行删了，测试依然全绿——因为 `__init__` 里还有回退，读的是同一个配置值。
那行显式传参其实是**冗余的**，而我的测试根本没在验证它声称的东西。
改名成 `test_engine_builds_strategy_on_the_right_market`，只验证结果，故事写进 docstring。
真正的逻辑在 `__init__` 的回退判断里——对那里做变异，**3 条测试变红**。
