## 六点四十五、修掉一个只在重启时暴露的缺陷：下穿后重启，趋势持仓永不按策略出场

### 一、起因：一个「长生不老」的持仓

`want_exit` 要求 `(not above) and prev_above`——必须是**新鲜下穿**。

而 `startup_entry` 的 docstring 写着：

> 进程如果在上涨途中重启，空仓状态下前一根也在上方，交叉条件永远不成立，就会一路空仓错过整段趋势。

进场侧为这个问题专门做了对账。出场侧的镜像是：

```
进程在【下跌途中】重启、持仓还在、下穿已经过去
  -> prev_above 已是 False
  -> want_exit 永远返回 None
  -> 只剩 25% 熔断一条路
  -> 而历史最深浮亏只有 -11.3%，熔断永远碰不到
  -> 仓位一路持有，穿过整个下跌趋势
```

### 二、先写一个会失败的测试

造序列：横盘 260 根（均线贴近 30000）→ 每根 −3% 急跌。逐步观察：

| 根 | above | prev_above | want_exit |
|---|---|---|---|
| 第 2 根 | False | True | **有**（首次跌破） |
| 第 3 根 | False | False | None |
| 第 5/8/12 根 | False | False | None |

**3 条测试红了。缺陷是真的。**

### 三、一个必须承认的事：我 43 轮的那个测试是假的

第 43 轮我做过信号级 parity，结论是「线上跑的就是回测过的那个策略」。
但那个测试里，**出场是我自己重写的**：

```python
elif not st["above"]:
    exits.append(i)
```

那正好是**回测**的语义，不是线上 `want_exit` 的语义。

**那个测试验证的是我假想的线上，不是真实的线上。** 这就是「测试因为错误的原因通过」。

这轮用真实的 `want_exit` 重跑 parity：连续运行下 **199 进场 / 199 出场，仍然完全一致**。
所以 43 轮的结论在连续运行时是对的——**分歧只在重启后暴露**。这比原来更精确，也更危险。

### 四、修复

去掉 `prev_above` 要求：持仓期间只要最后一根已收盘 4h 在均线下方就平。
**这正是回测的 `C[i] < sma(i)`。**

| 场景 | 修复后行为 |
|---|---|
| 连续运行 | 首次跌破那根出场，与原来完全相同 |
| 重启后 | 最后一根已在下方，立刻补出场 |
| 平仓单失败 | 下一跳还会再给信号，可重试，不卡死 |

措辞也分开：新鲜下穿说「下穿」，早已在下方说「跌破…此处补出场」。
混成一句话，事后查日志就分不清是按计划平的还是补平的。

### 五、修完后 2 个旧测试红了，性质不同

| 测试 | 性质 | 处置 |
|---|---|---|
| `test_cross_down_gives_exit` | 只是措辞 | 用双措辞解决，**没改测试** |
| `test_stale_price_does_not_trigger_phantom_stop` | **我引入的真回归** | 改 fixture |

第二个：它的 fixture 把 8 根 K 线全设成收盘 100.0，`SMA5 = 100.0`，
`above = (100 > 100) = False`——按回测语义本来就该出场。
那个测试要隔离的是**熔断路径**，必须先把 SMA 出场排除掉。
改成逐根走高（100..107）才真正隔离。

### 六、变异验证（本轮最关键的一步）

改了 fixture 之后，必须确认那条测试还在测它声称的东西：

| 变异 | 结果 | 结论 |
|---|---|---|
| 去掉 `_confirm_stop_price` 复核 | 测试失败 | 它确实在测陈旧价保护 |
| 把 `prev_above` 加回去 | **4 条测试失败** | 新测试确实钉住了缺陷 |

> 一条测试如果从来没失败过，它就不是测试。
> 一条测试如果为错误的原因通过，它比失败的测试更危险。

这轮两件事都撞上了，也都验了。

### 七、验证

231 个测试全绿（新增 8 条：策略层 5 + 引擎层 3）。
真实数据 parity 199/199 仍然一致。三服务 active，0 ERROR/CRITICAL，哨兵 OK。
