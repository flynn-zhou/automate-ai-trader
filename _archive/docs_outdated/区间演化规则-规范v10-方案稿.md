## 0 · 这份文件要解决什么

v9 的根本问题不是某个 if 写错了，是**同一个词在不同地方指不同的量**，于是同一句话在代码里能读出两种行为：

| 被混用的词 | 实际指的是 | 出现在哪 |
|---|---|---|
| 「下沿」 | (a) 区间下沿 P（二次确认后的回归值，可被突破） | `advance_trend` 返回值、`range_at()` 的 lo_b |
| | (b) 最低点关键价 K（实际最低点，不受确认滞后） | `key` 字段 |
| 「家族」 | (a) 换方向产生的新段 | 反转 |
| | (b) 同方向突破产生的新段 | 顺向突破 |
| 「边界」 | 反向边界 R / 顺向边界 P / 软边界 S / 关键价 K | 四个都叫「边界」 |

**v10 的第一条纪律：每个量只有一个名字，一个名字只指一个量。**

## 1 · 字典（双向镜像 · 唯一命名）

### 1.1 四个状态位 + 一个方向

| 符号 | 名称 | 下跌区间含义 | 上涨区间含义 | 谁驱动 | 能否越过后重置 |
|---|---|---|---|---|---|
| **D** | 方向 | DOWN | UP | 反转 / 同向突破 | — |
| **R** | **反向边界**（硬边界） | 硬**上**边界 | 硬**下**边界 | R4 养成期滚动极值 → 冻结 | 被收盘越过 ⇒ 反转，换家族 |
| **P** | **顺向边界** | **下沿** | **上沿** | R2/R5 二次确认推进 | 被收盘越过 ⇒ 突破，换家族 |
| **K** | **顺向关键价** | 最低点关键价 | 最高点关键价 | 每根 min/max，**无滞后** | 不触发任何事件，只记录 |
| **S** | **软边界** | 软**上**沿 | 软**下**沿 | R6 = R 那根的实体收盘；人工可覆盖 | 不得越过 R |

### 1.2 三条硬性禁令（v10 新增）

1. **「下沿 / 上沿」今后只指 P，不再指 K。** K 一律称「最低点关键价 / 最高点关键价」。
   依据：实测 10-22 18:00 时 P=82072.2 而 K=81605.5，**两者差 466.7 点**；
   把 K 标成「下沿」会让任何下游读者把突破线算错 466 点。
2. **S 不是 R。** S 是展示/风控位，**永远不参与任何触发判定**。
3. **K 不是 P。** K 用于「是否创出真正的新低/新高」，P 用于「区间画在哪」。

### 1.3 命名对照（v9 → v10）

| v9 里的东西 | v10 名称 | 备注 |
|---|---|---|
| `trend`（advance_trend 第一返回值） | **P** 顺向边界 | 变量名 `trend` 与「趋势」无关，纯属误导 |
| `hard` | **R** 反向边界 | |
| `soft` | **S** 软边界 | |
| `key` | **K** 顺向关键价 | |
| `lin` | **家族序号** | §4-D2 建议拆成 `family` + `segment` |
| `range_at()` 的 `lo_b`/`hi_b` | **(P,R)** 或 **(R,P)** 取决于 D | 字段序随方向翻转，是 v9 的踩坑源 |

## 2 · 状态机

```
        ┌──────────────── R1 人工指定起点 ────────────────┐
        ↓                                                │
   [ PRE 预热 ]                                          │
        │ 收盘越过 run_lo / run_hi                        │
        ↓                                                │
   [ 反转 ] ──────────────────────────────────────────┐  │
        │                                             │  │
        ↓                                             │  │
   [ 养成 forming ]  ← R4 滚动极值，直到不再创新逆向极值  │  │
        │                                             │  │
        │ R 冻结                                       │  │
        ↓                                             │  │
   [ 成形 settled ] ── R3 收盘越过 R ──→ [ 反转 ] ──────┘  │
        │                                                │
        └── 收盘越过 K（§4-D1）──→ [ 同向突破 ] ──────────┘
```

**转移表（v9 缺格的地方就是缺陷）**

| # | 从 | 到 | 触发条件 | 用哪个量 | 时点 | 触发后重置 |
|---|---|---|---|---|---|---|
| T1 | PRE | 养成 | `close > 历史最高` 或 `close < 历史最低` | 预热滚动极值 | 当根 | D、R、P、K 全部重建 |
| T2 | 养成 | 养成 | 逆向极值被刷新 | 当根 low（UP）/ high（DOWN） | 当根 | 只更新 R 与 S |
| T3 | 养成 | **成形** | 逆向极值**不再刷新** | 当根 low/high | 当根 | R、S 冻结 |
| T4 | 成形 | 反转 | `close` 越过 `R`（下跌：>R；上涨：<R） | R | 当根收盘 ⚠️ 见 D8 | D 翻转、家族号 +1 |
| T5 | 成形 | 同向突破 | `close` 越过 `K` | **K 的取值口径未定** | ⚠️ 见 D1 | 家族号 +1、方向不变 |
| T6 | 任意 | 任意 | 插针越过 R 但收盘收回 | 当根 high/low | 当根 | 只更新 R、S，**不换家族** |

> **v9 缺 T5 的「用哪根 K」定义，也缺 §4-D3 的最小反转裕度** —— 这是引擎在噪声上频繁换家族的直接原因。

## 3 · 六条规则 · 规范化

### R1 · 区间起点（人工指定）
**判据式**：给定 `(t0, D0, P0)`，从 `t0` 那根起以 D0 为方向、P0 为顺向边界初始化。
**现状**：v9 **没有这条**，起点由 `direction is None` 时的 `run_lo/run_hi` 自动孵化 ⇒ 见 D5。

### R2 · 顺向边界推进（P）
**下跌区间**：出现新低 `lo < P`，且**下一根**收盘 `c <= P_cand + TOL`（差不多到）⇒ P 下移，取确认那根的收盘；
未被击穿 ⇒ 候选**保留不丢弃**，P 不动。**上涨区间镜像**（`hi > P` 且 `c >= P_cand - TOL`）。
**待裁决**：TOL 单位 —— 见 D7。

### R3 · 反转
下跌区间 `close(t) > R`；上涨区间 `close(t) < R`。单根成立，不等第二根。
**前置条件**：**成形后（settled）才判**，养成期不判反转。
**待裁决**：是否需要最小裕度 —— 见 D3。

### R4 · 反向边界养成
反转后取**逆向走势的滚动极值**，直到某根**不再创出新的逆向极值** ⇒ 冻结为 R；
那一根的**实体收盘**即为 S。
**v10 明确**：`S = close(冻结那根)`，不是 confirm 那根。v9 实际取 confirm 那根的 `c` —— 见 D4。

### R5 · 顺向边界初始化
反转后 `P = 反转那根的极值`（下跌取 low，上涨取 high），之后按 R2 推进。
**说明**：R5 是 R2 的初始化特例，不是独立规则。v9 把它和 `advance_trend` 混在一起，导致 D1 的双下沿。

### R6 · 软边界
`S = R 冻结那根的实体收盘`；人工可覆盖；**不得越过 R**（下跌 `S <= R`；上涨 `S >= R`）。
**待裁决**：人工覆盖是「一次性改写」还是「永久钉死」 —— 见 D6。

## 4 · 不可判定点 D1–D8（每条都要裁决）

### D1 · 同向突破（T5）用哪个量判？

**现状实测**（2026-10-22 07:00 → 10-23 22:00 逐根）：

| 口径 | 首次触发 | 触发频次 |
|---|---|---|
| `close < K`（**当根** K） | **永不触发** | 649 根 DOWN 里 **0** 根成立（K 先 `min(lo)` 更新，`close >= lo >= K`，**恒假**） |
| `close < K_prev`（上一根 K） | 2026-10-22 09:00 | 4 小时内触发 5 次（09/10/13/14/16），把一整段单边下跌斩成 5 段 |
| `close < P`（v9 现状） | 2026-10-22 09:00 | 6 小时里只在 16:00 触发一次 |

- **甲（v9 现状）**：用 `P`。单边下跌只切一次；但 P 有确认滞后——10-22 09:00 收盘 83357 已在 P=84019.2 之下 662 点却不判突破，空转 5 小时。
- **乙**：用 `K_prev` + 强制「**成形后（settled）**才判」。语义干净；震荡里开段更频繁。

**建议：乙 + settled 捆绑。** 甲的「切一次」不是判据正确，是 P 的滞后偶然压住了次数。
乙在单边里是伪问题（K 一路下移，价格难得反弹回 K 之上），只有震荡里才频繁——而震荡里本来就应该切段。

**影响面**：改这条会改变全部家族编号，**引用过家族号的结论全部作废**。

### D2 · 「家族号 +1」代表什么？

**现状实测**：56 次递增 = **36 次反转 + 20 次同向突破**，最终家族号 57；
家族寿命中位 **9.0h**、均值 18.4h、**7/58 ≤ 3h**。

- **甲**：维持单一序号 —— 说「3 个家族」时，别人无法区分「3 段震荡」还是「3 段单边」。
- **乙**：拆成 `family`（换方向 +1）与 `segment`（方向内切段 +1），如 `#40.1 → #40.2 → #40.3 → #41.1`。

**建议：乙。** 10-22 07:00 → 10-23 03:00，价格从 84050 单边走 4.70% 到 80888，中间**没有一次超过 0.5% 的逆向摆动**，
引擎却报了 3 个家族。单一序号把「趋势里的切段」和「方向翻转」压成了同一个数。

**影响面**：只改编号，不改触发逻辑；历史家族号需重编。

### D3 · 反转要不要最小裕度？

**现状实测**：10-23 03:00「向上反转」裕度 = `81459.1 − 81420.0 = 39.1 点 = 0.048%`；
相对整波 4.70% 跌幅只回撤了 **14.3%**。而 `c ≈ 0.07%~0.17%`。

- **甲**：零裕度（v9 + 你规则集 R3 现状）。
- **乙**：加最小裕度 `REV_MIN`，如 `close > R × (1 + REV_MIN)`。

**建议：乙，但 REV_MIN 的取值必须在确认后由一次独立测量定，不能拍脑袋。**
0.048% 的越界在 0.07% 摩擦结构里连建仓成本都不覆盖，把它叫「趋势反转」是在给噪声命名。
**但**加裕度=引入新参数，必须防「扫参数挑最好格」（历史前向价值 −0.44%/笔）。
所以**先做只读敏感性表**（REV_MIN 0 → 0.20%，每 0.025% 一档，报家族数 / 中位寿命 / 中位段幅度），**看平台还是尖峰**。

**影响面**：**最大的一条**，它改变反转的定义本身。

### D4 · S（软边界）取哪根的收盘？

- **甲**：`S = close(冻结 R 的那根)` —— 你的规则集。
- **乙**：`S = close(确认 P 的那根)` —— v9 现状。

**建议：甲。** 乙会让 S 依赖「候选取到哪一根」，而候选推进本身受 TOL 影响，两个不确定量相乘 ⇒ 无法复核。
**实测差异**：#41 在 16:00 建立 R=82227.6，甲口径 S=81813.4；乙口径下 S 在 20:00 跳到 82145.0。

### D5 · 起点（R1）怎么喂？

- **甲**：保留自动孵化。
- **乙**：必须人工指定，未指定时只输出 PRE。

**建议：甲 + 乙并存。** 默认自动孵化用于批量回放，但**孵化出的第一个家族必须标 `seeded=false`**，
统计必须能按 `seeded` 分组 —— 自动孵化的第一个区间依赖数据从哪开始，是**边界效应**，不能和人工指定混在一个统计里。

### D6 · 人工覆盖软边界 = 一次性改写 还是 永久钉死？

**现状实测**：传入 `overrides={41: 81800.0}` 后，#41 的 S 在 16:00–22:00 **每根都是 81800.0**，
自动规则（「随失败反抽下移」）被整个屏蔽 —— 无覆盖时 20:00 会变成 82145.0。

- **甲**：一次性改写（只覆盖指定那根，其后恢复自动规则）。
- **乙**：永久钉死（v9 现状）。

**建议：甲。** R6 说「人工可调」，可调的是**读数**，不是**关掉规则**。乙等于给了一个能静默让 R2 失效的开关，
而 R2 是区间演化的主干。若确需长期钉死，应显式叫 `pinned` 并进统计分组。

### D7 · TOL 用绝对点数还是百分比？

**现状**：`TOL = 50.0`（绝对点）。50 点在 76k 时 **0.065%**，100k 时 **0.050%**，30k 时 **0.167%**。

**建议：改为比例 `TOL_PCT`。** 43 天单一行情里两者无差别，但跨年份跨价格区间时，
同一个旋钮会**静默改变判读灵敏度**且不被任何日志记录。
**注意：这条不是 bug，是没被写下来的设计选择。**

### D8 · 反转判据的同义反复

**现状实测**：#41 的 R=82227.6 是 **#41 自己在 16:00 建立的**；17:00→23:00 跌 341 点，03:00 反弹 322 点越过 R ⇒ 反转。
**一个家族创建了自己的死亡边界，一小时后用它宣布自己死了。**

- **甲**：维持（「区间终点由区间自己定义」，逻辑自洽）。
- **乙**：要求 R 独立于本家族。

**建议：维持甲，但加一条约束** —— `R` 至少在冻结后 **N_age 根**才可触发反转（建议 2~3）。
甲的语义在趋势市里没问题；真问题是 v9 里 R 冻结当根即可触发，等于没有任何「经历时间」要求。

## 8 · 变更纪律

1. **本文件冻结后，任何一条改动 = 新版本号（v10 → v11），不许就地改。**
2. **凡引用过旧家族号的结论，规则一变即作废**，不许复用。
3. **每条裁决（D1–D8）必须写进本文件并注明依据**；未裁决项不得在实现里「先按现状来」——
   那等于用默认值悄悄做了决定。
4. **实现之前，D3 必须先做敏感性表**（只读、不挑最优格），否则等于在参数空间里盲选。
