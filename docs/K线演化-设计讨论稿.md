## 一、核心概念：观察线（observation line）

用户原话：

> 「任何指标，比如黄金分割线，ema20/200 等都不是支撑线，只是观察线！
> 观察线就是不要直接动手上仓位，你得观察价格在这里的反应，
> 具体反应怎么看是支撑，怎么看是短暂停留！」

**「支撑线」是断言，「观察线」是观测位。**

- 说「EMA20 是支撑」—— 无法验证。跌破就改口说「有效跌破」，永远自洽。
- 说「价格在 EMA20 上有反应」—— 可以记录、可以数、可以统计。

**支撑不是线的属性，是反应的统计结果。** 一条线被反复守住，事后才叫支撑；
事前它只是个观测位。这是本项目「不预设结论」纪律最彻底的版本。

所以 K 线演化**不判断哪条线是支撑**，只记录**在每条观察线上发生了什么**。

## 二、观察线注册表（含周期）

| 类别 | 具体 |
|---|---|
| 均线 | EMA20 / 50 / 144 / 169 / 200（Web 已在算这五条） |
| 黄金分割 | 最近摆动高低点的 0.382 / 0.5 / 0.618 / 0.786 |
| 通道 | 唐奇安上轨/下轨 |
| 区间演化 | S 软边界、R 反向边界、P 顺向边界、K 关键价 |
| 结构位 | 前高/前低、摆动高低点、区间上下沿 |
| 心理位 | 整千、整百 |

**关键：每条线必须带自己的周期。**

EMA200 在 3m 上和 EMA200 在 1h 上，是完全不同的两条线。
一条观察线的身份是 `(种类, 周期, 参数, 价格)`，不是光一个名字。

一根 3m K 线，同时会遇到：EMA20(3m)、EMA200(1h)、黄金分割(日线摆动)、
唐奇安下轨(1h)、区间演化硬边界(15m)…… **这些混在一起，才是真实情形。**

## 三、K 线演化 = 记录四维，并列不嵌套

用户原话：「我们 K 线演化就是记录 K 线结构、观察线反应、量、区间演化空间位置
等多维结果而已！」

    1. K 线结构     实体/影线/收盘位置/方向
    2. 观察线反应   遇到了哪几条线、在线上发生了什么        <- 核心
    3. 量能         相对量、主动买卖比、集中度（3s 独有）
    4. 空间位置     区间演化到第几段/第几根、在哪个带里     <- 只是其中之一

**第 4 维是一维，不是框架。** 这是 v1 最大的错。

## 四、「是支撑还是短暂停留」怎么变成可算的

答案不是定义「支撑」，而是把「反应」记录到足够细。
对每根 K 线 x 每条碰到的观察线：

    触及        low <= p <= high
    来自方向     从上方来 / 从下方来
    穿透深度     (p - low)/p      扎进去多深
    收回幅度     (close - low)/p  收回多少
    收盘归属     收盘在线上 / 线下
    停留根数     连续几根 |close-p|/p < 阈值
    反应量能     触及这根的量 / 中位量
    主动方向     这根的 taker 买占比
    第几次来     这条线被第几次触碰

「守住」与「短暂停留」的区别藏在上面这些数里：

| | 守住 | 短暂停留 |
|---|---|---|
| 穿透深度 | 浅 | 深 |
| 收回 | 快、收盘回到线上 | 慢、收盘在线下 |
| 量 | 不大（没人真想打穿） | 很大 |
| 下一根 | 反向离开 | 继续走 |

**这两者的差别是数据能分辨的，而「这条线是支撑」不是。**

## 五、必须防的坑：当下读数 vs 事后确认

「之后涨了」是**事后信息**。混进当下读数，回测就会偷未来。
（本项目 1h 桶只在收盘落库、forming 桶永不持久化，就是为了防这个。）

字段分两组，**物理隔开**：

    at_bar    当下可观测   距离、触及、穿透、收回、量、停留根数
    forward   事后确认     之后 1/3/5 根的位移、是否真被守住

`forward` 只能用于事后研究，**绝不能参与当下判定**。
表结构和代码都要隔开，不能只靠自觉。

## 六、回溯是动态的，不是定死 N 根

用户原话：「也可能需要看 332/331/330 等，这个不是定死的，
因为有的 K 可能没什么意义，假如在区间中间的时候」。

做法：**不存「前一根是什么」，存「上一件同类事件是什么」。**

    since_last_break      距上次突破多少根
    since_last_touch(L)   距上次碰这条观察线多少根
    last_event_of_kind    同类事件的上一次是什么

这样「#334 收回」天然能引用 #333（它是上一个突破事件），
中间无意义的 K 不会打断链条 —— 隔 20 根也能连上。

**并且允许「无意义」：**

    state = neutral    没碰到任何观察线、量正常、在空间中间

区间中间大量 K 是 neutral。**强行给每根贴标签，就是在制造噪声。**

## 七、意图 = 状态转移的标签（v1 保留）

用户 #333/#334 的例子确立的：意图不是心理归因，是转移标签。

    #333  event=向上突破  prev_event=-
    #334  event=收回      prev_event=向上突破  since=1

合起来才是「假突破 / 诱多」，单卖任一根本拿不到。

**保留的反对意见：不许出现自由文本解释。**
不能写「主力在诱多」，只能写 `event=收回, prev_event=向上突破`。

注意 v2 修正：突破的对象**不限于区间演化边界**，
EMA、黄金分割、唐奇安、前高前低都能被突破。事件要带 `on_line`。

## 八、周期

用户：「具体多少周期算 K 线演化，我也说不好，3m 也可以」。

- **方法参数化周期**，`interval_ms` 是入参；
- **但每条观察线保留自己的周期**，不跟着 K 线周期走；
- 先做 **15m** 落地：能和区间演化逐根对齐验证，有现成参照物。
  3s 桶本地有 188k 根，3m 够用；但**没有参照物就无法验证算得对不对**。

## 九、我们真正的数据优势（保留）

看 1h K 线的人只有 4 个价格加 1 个量。
**本地有 187992 根 3s 桶，每笔带主动买卖方向（`is_buy`）。**

同一根长下影，别人只看到长下影，我们能看到它是：

- 一根 3s 桶瞬间砸下去的（流动性真空，恐慌）
- 还是慢慢阴跌 40 分钟然后拉回（承接，吸收）

**两者在 K 线上完全同形，含义相反。** 落成两个指标：

    集中度 conc = 最大单根 3s 桶量 / 这根 K 线总量
    内路径     极值发生在第几分钟、是否单边、是否 V 形

## 十、落地顺序

    1. 观察线注册表：先把 EMA 五条 + 唐奇安 + 区间演化四线 算出来落库。
       每条带自己的周期，价格按时间对齐（只用已收盘的，防偷未来）。
    2. 事实层：每根 K 线算结构 + 量能 + 内路径，落库，跑历史回填。
    3. 反应层：把「这根 K 遇到了哪些线、发生了什么」记录下来。
    4. 事件层：产出 event / prev_event / since，允许 neutral。
    5. 攒够连续数据 -> 才谈「哪些组合有意义」。

**第 5 步之前不碰判断标准。** 也不要跳过第 2 步直接建分类器 ——
那是本项目反复禁止的「把线索当策略」。

## 十一、口径 vs 判断标准

用户说「判断标准先不讨论」，同意。但必须区分：

| | 是什么 | 现在定不定 |
|---|---|---|
| **口径** | 「带量」怎么算 = 这根量 / 前 N 根中位量 | **要**，不定算不出来 |
| **判断标准** | 「带量 3.2 倍算不算好」、该不该进场 | **不要**，有数据再说 |

口径不是判断好坏，只是定义怎么算。**没有口径，连「如实描述」都做不到。**
做法：口径全部显式化、可改、记在库里，但不预设哪个值好。
