## 一、这是什么（用户已澄清，视为定稿）

**不是「给一根 K 线做分类」，是「每根 K 线收盘时，在已有演化状态上输出一份多维读数」。**

四条已确认：

1. 判断依据是**当前这根 + 前面所有 K 线的量、背景、位置**，不是单根孤立看；
2. 输出**多维度**结果，目的是**辅助进场与离场**；
3. **周期由使用者指定**（3m / 5m / 15m / 1h ...），同一套方法；
4. **每根都算**，接生产，形成连续的「K 线演化」流水，而不是按需调用一次。

用户原话：「其实就是给一根 K 线你判断当前状态，这个方法跟区间演化有点像，
接上生产，每一根都算是不是 K 线演化？」—— **是。**

## 二、最关键的结构：路径依赖，不是单根分类

用户的例子：

    编号 333：收盘突破硬边界          -> 读数：带量？高度？意图=突破？是否关键位？
    编号 334：收盘收回到硬边界内      -> 读数：原来是收回来了（同样多维）

用户的反问：「我们直接给你一根 K 线（编号 334），输出结果的时候，
是不是要看前一根 333 K 线，才能知道这根 K 线收回来了？」

**是，而且这不是「参考历史」，是逻辑上的必需：没有「出」过，就没有「收」。**

推论：

- 状态是路径依赖的，**不能重算单根**；
- #334 的输出**必须携带 prev_event**，否则这条读数无法解读；
- 「突破」与「收回」是**同一状态机的两次转移**，不是两个独立标签；
- **#333 + #334 合起来才是完整事实** —— 那是「假突破 / 诱多」。单卖任一根都拿不到。

## 三、意图 = 转移标签（这解开了上一稿的困局）

上一稿我反对做「意图分类器」，理由是心理归因无法标注。用户给出了正确做法：

    #333  收盘穿透 hard_up 且收盘在外  -> event = 向上突破
          附带：带量倍数、K 线高度、距关键位、主动买占比

    #334  收盘回到 hard_up 内          -> event = 收回
          prev_event = 向上突破        -> 组合解读 = 假突破候选

**这不是猜它想干什么，是如实记录发生了什么转移。** 转移可数、可回测、可样本外检验。

保留一半反对意见：**必须是转移标签，不能是自由文本解释。**
不允许出现「主力在诱多」这种句子，只能是 `event=收回, prev_event=向上突破`。

## 四、和区间演化的关系：同构、正交、复用词表

用户感觉「跟区间演化有点像」—— 实际比「有点像」更近。
`range/engine.py` 已在产出：

    birth                区间诞生
    区间成形
    向上突破 / 向下突破   <- 就是「突破」
    突破失败·反包          <- 「收回」的一半
    反向边界插针上移/下移
    R滚动
    向上反转 / 向下反转

**不该另造词表，应复用 + 扩展。**

| | 区间演化 | K 线演化 |
|---|---|---|
| 演化什么 | **结构**：边界在哪、段到第几 | **行为**：这根 K 干了什么 |
| 触发 | 边界被触碰或更新 | 任意一根都有读数 |
| 周期 | 15m（固定） | **用户指定** |
| 输出 | 状态 + 事件 | 多维读数 + 事件转移 |
| 落库 | `range_evolution` / `_events` | 新表（待定名） |

**两者正交，可并行跑。** 区间演化告诉你「墙在哪」，K 线演化告诉你「这堵墙正在被怎么撞」。

## 五、周期对齐（必须先说清的坑）

区间演化实际跑在 **15m**：

    range_evolution.ts      15m 时间戳
    range_evolution.ts_h    对应整点
    engine.py::load_1h      把 15m 聚成 1h 完整桶
    AI_RANGE_TICK_S=60      生产每 60 秒推进一次

**所以「硬边界」是 15m 结构的产品，不是任意周期的。**

用户指定 3m 算 K 线演化时，那个「突破硬边界」里的边界**仍然是 15m 的**。
我认为这是好事（高周期定结构、低周期看行为），但必须写进文档，
否则以后有人会以为「3m 的硬边界」是 3m 自己算的，然后对不上号。

## 六、输出结构（按用户例子设计）

每根 K 线一行：

    身份      ts, interval_ms, idx(编号)
    结构      fam, seg, seg_idx            当前 #fam.seg，段内第几根
    位置      ref_line, dist_pct, zone     最近哪条线 / 距多远 / 在哪两条之间
    形状      body_pct, upper_wick_pct, lower_wick_pct, close_pos, dir
    量能      vol, vol_rel, vol_slot_rel, taker_buy_ratio, conc
    内路径    path_shape, max_tick_share, t_low_min, t_high_min
    事件      event, prev_event, since_event_idx
    转移      transition                突破后第几根 / 收回第几根

**`event` + `prev_event` + `since_event_idx` 就是「要看 333 才知道 334」的落地形式。**

按用户的例子：

    #333  event=向上突破  prev_event=—           带量 3.2x  收盘位置 0.91  conc 0.38
    #334  event=收回      prev_event=向上突破    since=1    带量 0.6x  收盘位置 0.28

`prev_event=向上突破 + since=1 + event=收回` → 「刚突破一根就收回」，可直接查询、直接统计。

## 七、口径 vs 判断标准（这个区分要用户认可）

用户说「判断标准先不讨论」，同意。但必须区分两件事：

| | 是什么 | 现在定不定 |
|---|---|---|
| **口径** | 「带量」怎么算 = 这根量 / 前 N 根中位量 | **要**，不定算不出来 |
| **判断标准** | 「带量 3.2 倍算不算好」、突破后该不该进场 | **不要**，有数据再说 |

口径不是判断好坏，只是定义怎么算。**没有口径，连「如实描述」都做不到。**

做法：口径全部显式化、可改、记在库里（哪个 N、哪个基准），但**不预设哪个值好**。

## 八、我们真正的数据优势（上一稿保留）

看 1h K 线的人只有 4 个价格加 1 个量。
**本地有 187992 根 3s 桶，每笔带主动买卖方向（`is_buy`）。**

同一根长下影，别人只看到长下影，我们能看到它是：

- 一根 3s 桶瞬间砸下去的（流动性真空，恐慌）
- 还是慢慢阴跌 40 分钟然后拉回（承接，吸收）

**两者在 K 线上完全同形，含义相反。** 这是唯一的结构性优势，必须用上。

具体落成两个指标：

    集中度 conc = 最大单根 3s 桶量 / 这根 K 线总量
    内路径     极值发生在第几分钟、是否单边、是否 V 形

## 九、恐慌盘要先拆成三个事件（上一稿保留）

**A. 恐慌抛售**：单根跌幅 > k×sigma、量 > m×中位、随后 N 根回收 > x%
**B. 假破洗盘**：盘中探穿前极值 + 量峰 + **收盘**回到原区间内
**C. 挤空**：单根涨幅 > k×sigma + 量峰 + 主动买占比 > 0.5 + 持仓量骤降（若能取到）

判据完全不同，**必须先分清用户指的是哪个**。

## 十、落地顺序

    1. 把「口径」写成一页定义：带量怎么算、集中度怎么算、位置怎么度量。
    2. 事实层：每根 K 线算出来落库，跑历史回填。不涉及任何判断。
    3. 喂区间演化已有的边界，产出 event / prev_event / since。
    4. 攒够连续数据 -> 才谈「哪些组合有意义」。

**第 4 步之前不碰判断标准。** 也不要跳过第 2 步直接建分类器 ——
那是本项目反复禁止的「把线索当策略」。
