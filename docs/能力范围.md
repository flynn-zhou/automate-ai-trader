## 0 · 一句话定位

在 100 USDT 量级的合约账户上，做**长期正期望**的加密自动交易；
区间演化（v11 四线）负责「理解市场结构」，持仓守卫负责「管住每一笔仓」。

**明确不做的事**（写下来是为了以后不被"顺手加上"）：

- 不做高频剥头皮（成本结构决定：往返 0.11% 摩擦吃掉大部分短差）
- 不做马丁格尔 / 被套加仓（已裁决：止损 + 重进，只在赢的仓上加）
- 不用终值判断策略好坏（复利是混沌放大器，看单笔均值 / t 值 / 逐年）

## 2 · 区间演化 v11

### 2.1 四条线（唯一命名，禁止混用）

| 符号 | 名称 | 谁驱动 | 越过会怎样 |
|---|---|---|---|
| **D** | 方向 | 反转 / 同向突破 | — |
| **R** | 反向边界 | 养成期滚动极值 → 冻结 | 被收盘越过 ⇒ **反转**，换家族 |
| **P** | 顺向边界 | 二次确认推进 | 被收盘越过 ⇒ **突破**，换段 |
| **K** | 顺向关键价 | 每根 min/max，无滞后 | 不触发任何事件，只记录 |
| **S** | 软边界 | R 那根的实体收盘 | 展示/风控位，**永不参与判定** |

**三条禁令**（v10 规范原话，踩过坑）：

1. 「下沿/上沿」只指 P，不指 K。实测两者曾差 466.7 点。
2. S 不是 R，S 不参与任何触发判定。
3. K 不是 P：K 用于「是否创真新低」，P 用于「区间画在哪」。

### 2.2 已实现的 v10 待裁决项

| 项 | 内容 | 实现 |
|---|---|---|
| D1 | 同向突破用哪个量 | ✅ 改用 key_prev（M1/M2），不再用 P |
| D2 | 家族号含义 | ✅ 拆 family / segment，显示 #fam.seg（M3） |
| D4 | 软边界取哪根收盘 | ✅ 取冻结 R 那根的实体收盘（M5） |
| D7 | TOL 单位 | 🟡 50 → 30，**仍是绝对点数**，未比例化 |
| C1/C2 | 输入自证与丢桶告警 | ✅ 不再静默（M6） |
| C3 | 事件带参照量与裕度 | ✅（M7） |

### 2.3 尚未实现（需裁决后才能动）

- **D3 反转最小裕度**：实测有 0.048% 的越界被当作「反转」，小于 0.07% 摩擦成本。
  加 REV_MIN 等于引入新参数 ⇒ 必须先做**只读敏感性表**（0 → 0.20%，每 0.025% 一档），
  看平台还是尖峰，禁止扫参数挑最好格。
- **D5 起点播种**：自动孵化出的第一个家族必须标 seeded=false，统计要能分组。
- **D6 人工覆盖语义**：现在传入 override 会永久钉死，等于一个能静默关掉 R2 的开关。
- **D8 R 的年龄约束**：现在 R 冻结当根即可触发反转，等于没有「经历时间」要求。

## 3 · 功能型方法

### 3.1 按时间点回看区间 as_of

**问**：2026-10-01 12:00 那一刻，区间画在哪、是哪一段？
**答**：两个入口，口径必须一致（测试里对同一 ts 校过）。

| 入口 | 用途 | 语义 |
|---|---|---|
| engine.as_of(when, bars) | 研究 / 无库 | 从 CSV 重算，取 ts <= 目标的最后一根 |
| store.state_at_dict(sym, ts) | 生产快路径 | 一条 SQL，权威 |

返回除四条线外**还带那根 K 线的 OHLCV**——只给线不给价格，读者无法判断区间相对价格的位置。
早于第一根数据返回 None（不是空 dict），调用方要能区分「没数据」和「未成形」。

HTTP：GET /api/range/asof?when=2026-10-01 12:00

### 3.2 K 线意图识别（未实现）

守卫的 decide(..., kline=) 已留挂载点，契约是：

    kline.intent         : breakout / continuation / exhaustion / distribution / none
    kline.panic_flush    : bool   是否恐慌插针
    kline.volume_regime  : 放量 / 缩量 / 常态
    kline.low / .atr     : 用于插针深度

**硬约束：P0 保命分支禁止调用 K 线判断。** 亏损到了就必须走，
不能因为「K 线看着像洗盘」而留仓。

## 4 · 参数权威关系（重要）

**数据库是唯一权威。env / yaml 只在首次启动时播种一次。**

    首次启动：库为空 → 把 env 的值写进库（seed_from）→ 之后只认库
    非首次：  库非空 → env 被忽略，页面改动（写库）才生效

为什么必须这样：空库时若直接回落硬编码默认值，env 里写的 AI_PAPER_BALANCE=300
会被**静默忽略**，系统拿 100U 去算仓位，而页面上还显示 100——用户以为自己配的是 300。
这条缝有专门的测试盯（test_first_run_seeds_from_env_not_hardcoded_defaults）。

**要让 env 重新生效，必须显式清空 app_settings 表。**

### 实时生效的原理

引擎构造时保存的是**对象引用** self.tcfg = cfg.trading，每次决策现读字段（不缓存数值）。
所以 settings.apply_to() 就地改字段，**下一次决策立刻用新参数**，无需重启。
这是隐式契约，有测试（test_apply_to_mutates_the_live_object）盯着。

## 5 · 硬不变量

违反任何一条都是 bug，不是「参数选择」：

1. **爆仓必须晚于止损**：爆仓距离 >= safety_multiple × 止损距离（默认 2.5×）
2. **22x 的物理上限**：爆仓距离 = 1/22 − 0.5% = 4.045% ⇒ 止损上限 1.618%（2.5×）
3. **仓位由风险反推**：notional = R / 止损距离，杠杆只是结果与上限检查
4. **保证金比例是上限，不是输入**：40%/60% 是 CAP，不能反过来用它算止损
5. **止损永不后退**：棘轮只允许朝有利方向移动
6. **P0 优先于一切**：保命分支不允许被 K 线判断否决
7. **不加输的仓**：被套加仓已裁决废弃，只在赢的仓上加
8. **缺失边界是 None，不是 0**：填 0 或前值都是伪造数据

## 11 · 多品种：为什么只做了一半

订阅清单（`market/subscription.py`）已完成：DB 权威、增删、启停、首次播种。
但**行情管道仍是单品种**，原因是硬性的：

```
store.py:  CREATE TABLE bars (
              interval_ms INTEGER NOT NULL,
              open_time   INTEGER NOT NULL,
              ... PRIMARY KEY (interval_ms, open_time)   <-- 没有 symbol 列
          )
```

要真正收多品种，必须依次改三处，且每一处都会牵动现有 782 项测试：

1. **bars 表加 symbol**（主键改 `(symbol, interval_ms, open_time)`），并迁移旧数据
2. **Feed 支持多实例**（现在是 `RestMarket` + `AggTradeWS` 各一个，写死 `cfg.market.symbol`）
3. **Store 查询按 symbol 过滤**（`query_bars` 等所有调用方）

这不叫「搬个模块」，叫改数据模型。已按此评估，等用户裁决后再动。

**注意区分**：订阅 = 收行情；交易品种仍是单一字段 `cfg.trading.symbol`。
订阅五个币不等于在五个币上开仓。有一条测试专门钉这个区别。
