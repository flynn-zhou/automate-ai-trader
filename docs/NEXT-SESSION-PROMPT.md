```text
接手 D:\workspace\automate-ai-trader 这个项目。请先读 docs/HANDOFF-DSH-SESSION.md
（这是主交接文档，读完就能接上），然后读 docs/K线演化-设计讨论稿.md。

几条必须知道的：

1. 这个项目现在**没有任何在生产运行的交易策略**，只是记录行情与区间演化。
   equity 只有 0.007127 USDT，开不出任何一手。不要以为"系统在跑"等于"有策略在跑"。

2. 用户是**出钱、提方向**的人，不做实现。他的原话："任何指标，比如黄金分割线，

3. **先写探针打印真实值，再写测试。** 这个项目反复出现"测试通过但功能没接线"。
   测试绿只说明旧行为没坏。

4. **只读生产库，绝不写。** data/market.db 和 data/market_range.db 生产在用。
   新表建在独立库 data/kbar.db。

5. 已装 git，远端在 GitHub。**改大文件用 edit 不要用 write**（曾经一次 write
   把 1836 行的 engine.py 覆盖成 867 行，当时没 git，靠从服务器拉回才救回来）。

6. 全仓测试跑 `python -m pytest tests -q`，当前 913 passed。你的改动不能让它变红。

先做设计文档里的"第十二、实现顺序"第 1 步（观察线计算与落库），
做完第 1 步停下来汇报探针结果，不要一口气做到第 5 步。
```

## 为什么这么写

| 段落 | 作用 |
|---|---|
| 指向两份文档 | 新会话不重读历史，直接从定稿开始 |
| 任务一句话 | 「实现 K 线演化」，不是「讨论」也不是「优化」 |
| 不要再问三条决策 | 防止新会话重新设计已经拍定的东西 |
| 没有策略 / 0.007U | 防止误以为有策略在跑 |
| 观察线不是支撑线 | 这是定位，偏离了做出来的东西就是错的 |
| 探针优先 | 项目里最贵的一条教训 |
| 只读生产库 | 写坏了生产就出事 |
| edit 不用 write | 真实事故 |
| 只做第 1 步 | 防止一口气实现完然后错在根上 |

## 如果你想让新会话多做一点

把最后一段改成：

```text
按设计文档"第十二、实现顺序"依次做第 1 到第 4 步，
每一步做完先跑探针验证，再进下一步。第 5 步（事后层）先不做。
```

**不建议**让它一路做到第 5 步就结束 —— 中途不验收，错在根上会浪费一整轮。
