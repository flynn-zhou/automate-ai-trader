## 六点四十七、把六道安全闸画进大屏因果链，并修掉纸面/实盘两本账互串的两处缺陷

### 一、大屏一直少了一环

趋势因果链早就画得很完整：`4h K线 → SMA200 → 现价 → 趋势方向 → 动作 → 触发线 → 等待预期`。

但它漏了**安全闸**。后果是一句谎：

```
动作：空仓等待
开多触发线：涨到 82337.4（还需 +5.16%）并收盘确认
```

这行字暗示「价格到了就会开」。可六道闸任何一道拦住（数据源 DOWN、峰值回撤熔断、
连亏冷却、当日亏损超限），实际都不会开。用户会盯着「涨到 82337 就开」等一整天。

> 漏掉「为什么不能开」的因果链，不是因果，只是愿望。

### 二、修法

`engine.state()` 增加 `guard` 字段（和趋势状态一次轮询拿到），大屏把闸的状态插进
**「趋势方向」之后、「动作」之前**——这正是真实的因果顺序：数据 → 判断 → 有没有资格动手 → 动作。

| 状态 | 显示 |
|---|---|
| 放行 | 安全闸放行，回撤 0.0%（硬停线 60%） |
| 拦截 | 安全闸拦截：不会开仓 + 人话原因 |
| 未接入 | 安全闸：未接入（开仓是否放行未知） |

第三种是特意加的。没有 guard 时不能默认「可以开」——
**把「不知道」显示成「没问题」是最糟的一种谎**。所以 `can_open` 返回 `None`。

拦截时「动作」那行也改写：`动作：空仓等待（闸未放行，即使触发也不开）`，
触发线追加 `（当前被上面那道闸拦住，不会执行）`。

### 三、用真浏览器验的，不是只看代码

JS 的运行时错误在语法检查里看不见（`node --check` 只查语法）。起了隧道 + 真实浏览器读页面实际文本：

```
4h K线 419 根 → SMA200 82337.4 → 现价 77974.6（-5.30%）→ 下跌趋势（价在均线下方）
→ 安全闸放行，回撤 0.0%（硬停线 60%）
→ 动作：空仓等待 → 开多触发线：涨到 82337.4（还需 +5.60%）并收盘确认
```

页面级 console 无报错（只有 MetaMask 扩展自己的警告）。

> 截图工具返回了图片但视觉引擎读不了，建议 `npx @liustack/modlens doctor` 查一下。
> 不影响结论——文本观察比截图更硬。

### 四、顺手查完另外两处，都是真的

**1) 纸面余额把实盘的盈亏算进来了**

没有 `executor_state` 时纸面余额用 trades 重建：`balance = paper_balance + realized_pnl()`，
而 `realized_pnl()` 无差别求和所有已平仓交易。造数据实测：

| | 纸面 | 实盘 | 恢复出的纸面余额 | 正确值 |
|---|---|---|---|---|
| 实测 | +10 | −50 | **60** | 110 |

纸面账户和真钱账户是两本账。串了之后纸面的权益/回撤/风控闸全部失真——
而这套系统正要从纸面切实盘，正是最需要两本账干净的时候。

**2) 实盘对账关闭遗留持仓时把 paper 标记写死了**

`reconcile_live()` 里三处硬编码 `paper: 0`，而同一个文件另外五处都用 `1 if ex.name == paper else 0`。
**五处算对、三处写死——这是疏漏，不是有意。**

后果：从纸面切实盘后，遗留的纸面仓被对账关闭时记成真实交易。
修：`attach()` 把 `paper` 带进 `self.pos`，对账关闭时按它记账。

注意这里必须分开钉：**接管交易所实际持仓时 `paper=0` 是对的**（交易所真有币），
所以测试同时钉了「纸面仓仍记纸面」和「真实仓仍记真实」。

三组变异检查，各自回退后对应测试变红。全量 **248 个测试通过**（新增 5 条）。
三服务 active，0 ERROR/CRITICAL，哨兵 OK。

### 六、这轮学到的

> 「因果表达」不只是把算出来的数字摆出来，
> 还要把【什么条件下这个数字不会兑现】一起摆出来。
> 前者是状态展示，后者才是因果。
