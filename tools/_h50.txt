## 六点五十、全栈演练：真实引擎跑真实历史，232 笔逐一对齐

### 一、为什么做这件事

前几轮分别修过出场逻辑（`want_exit`）、下单路径（`spot.market_order`）、记账口径，每处都有单元测试。
但 **开仓 → 持仓 → 盯止损 → 出场 → 平仓 → 记账 → 统计** 这一整条链路，从来没有作为整体跑过。**趋势策略至今 0 笔成交。**

> 一个从没跑通过的整体流程，各部分分别「测试通过」并不等于它真的能跑。
> 2026-11-01 就吃过这个亏：读 `bar.vol`（真实字段是 `volume`），每 3 秒抛一次 AttributeError，被上层 `except` 吞成「决策步骤异常」——系统看起来在跑、看板有数据、决策在写，实际上从未评估过。

### 二、做法与结果

`tools/rehearse.py`：真实 4h 现货历史（**15999 根**，2019-07-14 ~ 2026-11-01）逐根喂给**真实 `DecisionEngine._step_trend`**，用**真实 `PaperExecutor`**（含滑点 + 0.1% 手续费）成交、**真实 `TradeDB`** 记账，最后把 `trades` 表与回测逐笔对齐。

```
回测：进场 232 次，出场 232 次
引擎：进场 232 次，出场 232 次
→ 232 笔进场、232 笔出场，下标逐一对齐
```

**这是第一次端到端证明：线上跑的代码就是回测过的那个策略**，而不只是「信号函数」一样。

记账也对得上：

| 项目 | 数值 |
|---|---|
| 起始 → 最终 | 100U → **1045.05U** |
| 净盈亏 | **+945.05U** |
| 手续费合计 | 233.65U |
| 最大回撤（逐笔结算） | **31.13%** |
| 峰值 | 1129.90U |
| mfe/mae 全为 0 的笔数 | **0**（两列真的接上线了） |

对比回测 `+890%`（100U → 990U）：非常接近，差在滑点与双边手续费。
回撤 `31.13%` vs 回测 `47.7%`，差的正是那个早已确立的区分：回测逐根**盯市**（含浮动），这里只按逐笔结算，**已实现口径会低估回撤**。

> 数据已从 13999 根长到 **15999 根**，交易数随之 **199 → 232**。之前引用的 199 笔是旧快照，以后说笔数要标数据截止日。

### 三、我抓到了自己测试的假通过

把演练缩成不依赖网络的单元测试，3 条全绿。做变异检查时发现：**把 `want_exit` 改成恒不触发，测试依然全绿。**

查下去：合成序列是 `30x100 → 5x120 → 25x90`，那个 −25% 下探直接触发了**熔断止损**——决策日志写得清楚：

```
平仓 熔断止损 90.0（跌破 25.0%）：净 -25.1171U
```

**测试从头到尾没走过 SMA 出场那条路**，却在声称验证「SMA 出场」。

改法：下穿必须**温和**——跌破均线，但远不到 25%。改成 `30x100 → 5x110 → 25x106`（相对 110 只跌 3.6%），现在平仓原因是：

```
4h 收盘 106.0 下穿 SMA20 106.1（趋势结束，平多）
```

重做变异，三个都钉住：

| 变异 | 结果 |
|---|---|
| 出场信号恒不触发 | 2 条**断言失败** |
| 开仓信号恒不触发 | 2 条**断言失败** |
| 不写 trades 表 | 1 条报错 |

> 过程中还有两次我自己的假象：变异写成函数体造成 `IndentationError`，返回码非零被误判成「钉住了」。后来改成语法安全的变异 + 先 `py_compile` 验证 + 区分「断言失败」和「语法错误」，才算数。

### 四、一次没有根据的怀疑，也记下来

### 五、验证

**258 个测试全绿**（新增 3 条生命周期测试），363 个脚本语法正确，三个变异全部有效钉住。
